src/utils/storage.py

Storage & safety

Every other module reads and writes through two functions here. This is the layer that makes "safely" true: a save either lands completely or not at all, and the previous version is never gone for good.

How a save actually happens

save_json() never writes to the target file directly. It:

  • copies the current file into data/.backups/, tagged with a timestamp and a monotonic counter so rapid saves don't collide;
  • writes the new content to a temp file in the same directory;
  • calls os.replace() to swap it into place — atomic on POSIX and Windows, so a crash mid-write can't leave a half-written JSON file behind;
  • on any exception, deletes the temp file and re-raises, leaving the original untouched.

Only the last MAX_BACKUPS_PER_FILE (10) backups per file are kept.

  • load_json(path, default) Reads a JSON file, or returns default if it doesn't exist yet.
  • save_json(path, data) Backs up the current file, then atomically overwrites it.
  • ValidationError Raised by every module below when data fails a structural check before it's saved.

World: locations & items

The tile map and the loot catalog live in one file, because a location's loot list and its exits map are only meaningful in relation to each other.

Locations

create_location(location_id, name, description="", x=None, y=None, area=None, exits=None, loot=None)

Creates a tile. Fails if location_id is already taken, or if (x, y) is already occupied by another location.

ParameterTypeDescription
location_idstrUnique key. See id convention below for multi-tile places.
namestrRequired, non-empty.
x, yint | NoneThe single global coordinate system — no separate local grid. No two locations may share the same non-null pair.
areastr | NoneGroups tiles that make up one narrative place, e.g. "castle_courtyard".
exitsdict[str, str]Direction → target location id. Direction must be one of north/south/east/west/up/down/in/out.
lootlist[str]Item ids found here.

ReturnsWarnings — any exit or loot id that points at something that doesn't exist yet.

RaisesValidationError on a duplicate id, a missing name, an unrecognized exit direction, a non-string exit target, a non-string area, or a coordinate collision with an existing location.

  • update_location(location_id, **fields) Merges given fields onto the existing record, then re-validates the result (including the coordinate check).
  • delete_location(location_id, force=False) Blocked if another location still exits into this one — pass force=True to delete anyway.
  • get_location(location_id) Returns the record, or None.
  • list_locations() Returns the full {id: record} dict.
  • list_locations_by_area(area) Returns only the locations tagged with that area.

Items & loot

create_item(item_id, name, type, category, rarity, value=0, weight=0, owner=None, description="")

Adds an entry to the loot catalog. Locations reference items by id — the catalog doesn't know or care which locations carry a given item. type, category, and rarity have no defaults — every item must be created with all three.

ParameterTypeDescription
item_idstrUnique key, e.g. "dagger_001".
namestrRequired, non-empty.
typestrRequired, non-empty. The material/quality prefix, e.g. "Iron", "Silver", "Rune", "Ethereal".
categorystrRequired. One of Weapon, Armor, Clothing, Jewelry, Food, Drink, Tool.
raritystrRequired. One of Common, Uncommon, Rare, Unique.
valueint | floatSell/score value; free-form for your engine.
weightint | floatCarry weight; free-form for your engine.
ownerstr | NoneThe only field that may be None — and only when rarity isn't Unique. Unique items must be created with an explicit owner.

ReturnsWarnings — recomputed across the whole file, since a new item can resolve loot references that were dangling before.

RaisesValidationError on a duplicate id, a missing name/type, an invalid category/rarity, a Unique item with no owner, a non-string owner, or a non-numeric value/weight.

  • update_item(item_id, **fields) Partial update, same merge-then-validate pattern.
  • delete_item(item_id, force=False) Blocked if a location still lists it as loot — pass force=True to override.
  • get_item(item_id) Returns the record, or None.
  • list_items() Returns the full {id: record} dict.
Forward references are allowed on purpose

An exit that points at a location you haven't built yet, or loot that names an item you haven't stocked yet, is not rejected. It's normal to sketch a map before filling it in. Every create/update call returns a Warnings object listing what's still dangling — check .messages, or call check_dangling_references() any time to re-scan the whole file.

Multi-tile areas

A twelve-tile courtyard isn't one record with a list of tiles inside it — it's twelve ordinary locations that happen to share an area tag. Each tile keeps its own exits, so walking from one flagstone to the next inside the courtyard works exactly like walking between any other two locations.

Id convention

There's no separate local grid for tiles inside an area — x/y stay the single global coordinate system already on every location. The convention is to fold the area name and global coordinate into the id itself: 

f"{area}_{x}_{y}"   # -> "castle_courtyard_12_7"

That makes a neighboring tile's id computable instead of guessed, and reads as a position at a glance instead of an opaque counter like castle_courtyard_014. Put the human-facing label in name instead — id stays mechanical.

Two courtyard tiles, connected to each other:

python
world_data.create_location(
    "castle_courtyard_0_0",
    name="Castle Courtyard — Northwest Corner",
    x=0, y=0,
    area="castle_courtyard",
    exits={"east": "castle_courtyard_1_0"},
)
world_data.create_location(
    "castle_courtyard_1_0",
    name="Castle Courtyard — Fountain",
    x=1, y=0,
    area="castle_courtyard",
    exits={"west": "castle_courtyard_0_0"},
)

world_data.list_locations_by_area("castle_courtyard")
# -> {"castle_courtyard_0_0": {...}, "castle_courtyard_1_0": {...}}
cli
python3 -m src.utils.cli location create \
  --id castle_courtyard_0_0 \
  --name "Castle Courtyard — Northwest Corner" \
  --x 0 --y 0 --area castle_courtyard \
  --exit east=castle_courtyard_1_0

python3 -m src.utils.cli location create \
  --id castle_courtyard_1_0 \
  --name "Castle Courtyard — Fountain" \
  --x 1 --y 0 --area castle_courtyard \
  --exit west=castle_courtyard_0_0

python3 -m src.utils.cli location list --area castle_courtyard

Placing a thirteenth tile on a coordinate already in use is rejected, not silently overwritten:

python
world_data.create_location("oops", name="Oops", x=0, y=0)
# ValidationError: Location 'oops' shares coordinates (0, 0)
# with existing location 'castle_courtyard_0_0'.

NPCs

NPCs are placed by location_id. Placement is optional — an NPC with location_id=None exists in the roster but isn't standing anywhere yet.

create_npc(npc_id, name, description="", location_id=None, dialogue=None, friendly=True)
ParameterTypeDescription
npc_idstrUnique key, e.g. "keep_warden".
namestrRequired, non-empty.
location_idstr | NoneWhere they're standing; None if unplaced.
dialoguelist[str]Lines, in whatever order your engine reads them.
friendlyboolDefaults to True.

ReturnsWarnings — a non-null location_id that doesn't match an existing location.

RaisesValidationError on a duplicate id, a missing name, or a wrong-typed location_id / dialogue / friendly.

  • update_npc(npc_id, **fields) Partial update, merge-then-validate.
  • delete_npc(npc_id) No reference protection — nothing else points at an NPC by id.
  • get_npc(npc_id) Returns the record, or None.
  • list_npcs() Returns the full {id: record} dict.

Triggers

A trigger is an envelope, not a scripting language. condition and action are free-form dicts — this module only checks that they're dicts and leaves the keys inside them to whatever engine code eventually reads them.

create_trigger(trigger_id, type, location_id=None, condition=None, action=None, repeatable=False)
ParameterTypeDescription
trigger_idstrUnique key.
typestre.g. "on_enter", "on_talk", "on_item_pickup". Required, non-empty.
location_idstr | NoneWhere it fires, if location-bound.
conditiondictFree-form; interpreted by your engine.
actiondictFree-form; interpreted by your engine.
repeatableboolWhether it can fire more than once.

ReturnsWarnings — a non-null location_id that doesn't exist yet.

RaisesValidationError on a duplicate id, a missing/non-string type, a non-string location_id, a non-dict condition/action, or a non-bool repeatable.

  • update_trigger(trigger_id, **fields) Partial update, merge-then-validate.
  • delete_trigger(trigger_id) No reference protection.
  • get_trigger(trigger_id) Returns the record, or None.
  • list_triggers() Returns the full {id: record} dict.
src/utils/cli.py

CLI reference

A thin argparse layer over the four modules above, so you can build the world from a terminal without opening a Python shell. Every entity supports the same five verbs.

shape of every command
python -m src.utils.cli <location|item|npc|trigger> <create|update|delete|get|list> [flags]
  • location create/update --id --name --description --x --y --area --exit DIR=ID --loot ITEM_ID  (repeat --exit/--loot; update adds --clear-exits/--clear-loot)
  • location delete --id  (--force to override reference protection)
  • location list --area ID  optional — narrows the listing to one area's tiles
  • item create/update --id --name --type --category --rarity --description --value --weight --owner  (--category/--rarity are restricted to the valid sets; update only: --clear-owner)
  • item delete --id  (--force to override)
  • npc create/update --id --name --description --location ID --dialogue LINE --hostile  (update only: --friendly to flip back, --clear-location)
  • trigger create/update --id --type --location ID --condition JSON --action JSON --repeatable  (update only: --not-repeatable, --clear-location)
  • <entity> get / list get --id ... prints one record; list prints the whole collection — both as JSON.
Exit codes

Success prints a confirmation line (plus any warnings, to stderr) and exits 0. A ValidationError — duplicate id, bad field, blocked delete — prints error: ... to stderr and exits 1, so it's safe to chain commands in a script and check $?.

Toy example: the Sunken Keep

A two-room map with a key, a warden, and a trigger that hands over the key — built two ways: as calls against the Python modules, and as the equivalent CLI invocations. Either column produces the same three JSON files.

i.

Sketch the courtyard with an exit that doesn't exist yet

Real design work is nonlinear — you know the armory is north of the courtyard before you've written the armory. Create the courtyard anyway; the warning is just a note to come back.

python
from src.utils import world_data

warnings = world_data.create_location(
    "courtyard",
    name="Sunken Courtyard",
    description="Rain pools between cracked flagstones.",
    exits={"north": "armory"},
)
print(warnings.messages)
# ["Location 'courtyard' exit 'north' -> unknown location 'armory'."]
cli
python3 -m src.utils.cli location create \
  --id courtyard \
  --name "Sunken Courtyard" \
  --description "Rain pools between cracked flagstones." \
  --exit north=armory
ii.

Build the armory, resolving the exit

python
world_data.create_location(
    "armory",
    name="Old Armory",
    description="Racks of rusted spears.",
    exits={"south": "courtyard"},
    loot=["rusty_key"],  # item doesn't exist yet either
)
cli
python3 -m src.utils.cli location create \
  --id armory \
  --name "Old Armory" \
  --description "Racks of rusted spears." \
  --exit south=courtyard \
  --loot rusty_key
iii.

Add the key, place the warden, wire the trigger

python
from src.utils import npc_data, trigger_data

world_data.create_item(
    "rusty_key", name="Rusty Key",
    type="Iron", category="Tool", rarity="Common", value=0,
)

npc_data.create_npc(
    "keep_warden",
    name="The Keep Warden",
    location_id="courtyard",
    dialogue=["The armory's locked. Has been for years."],
)

trigger_data.create_trigger(
    "warden_grants_key",
    type="on_talk",
    location_id="courtyard",
    condition={"npc": "keep_warden"},
    action={"give_item": "rusty_key"},
    repeatable=False,
)
cli
python3 -m src.utils.cli item create \
  --id rusty_key --name "Rusty Key" \
  --type Iron --category Tool --rarity Common --value 0

python3 -m src.utils.cli npc create \
  --id keep_warden --name "The Keep Warden" \
  --location courtyard \
  --dialogue "The armory's locked. Has been for years."

python3 -m src.utils.cli trigger create \
  --id warden_grants_key --type on_talk \
  --location courtyard \
  --condition '{"npc": "keep_warden"}' \
  --action '{"give_item": "rusty_key"}'
iv.

Testing during development

The suite runs against a throwaway directory, never the real data/ folder, so you can write a test the same afternoon you write the feature without any cleanup step.

tests/conftest.py
import pytest
from src.utils import npc_data, storage, trigger_data, world_data

@pytest.fixture(autouse=True)
def isolated_data_dir(tmp_path, monkeypatch):
    data_dir = tmp_path / "data"
    monkeypatch.setattr(storage, "DATA_DIR", data_dir)
    monkeypatch.setattr(storage, "BACKUP_DIR", data_dir / ".backups")
    monkeypatch.setattr(world_data, "WORLD_PATH", data_dir / "world.json")
    monkeypatch.setattr(npc_data, "NPCS_PATH", data_dir / "npcs.json")
    monkeypatch.setattr(trigger_data, "TRIGGERS_PATH", data_dir / "triggers.json")
    yield data_dir

Because it's autouse, every test below gets a clean, empty data directory without asking for it by name. The delete-protection behavior used above is covered in tests/test_world_data.py:

tests/test_world_data.py
import pytest

from src.utils import world_data
from src.utils.storage import ValidationError

def test_delete_location_blocked_when_referenced_by_another_exit():
    world_data.create_location("forest_1", name="Dark Forest", exits={"north": "forest_2"})
    world_data.create_location("forest_2", name="Deeper Forest", exits={"south": "forest_1"})
    with pytest.raises(ValidationError):
        world_data.delete_location("forest_2")
    # Still there -- the blocked delete must not have partially applied.
    assert world_data.get_location("forest_2") is not None

def test_delete_location_force_overrides_reference_protection():
    world_data.create_location("forest_1", name="Dark Forest", exits={"north": "forest_2"})
    world_data.create_location("forest_2", name="Deeper Forest", exits={"south": "forest_1"})
    world_data.delete_location("forest_2", force=True)
    assert world_data.get_location("forest_2") is None
Run it

From the project root, with the virtualenv active:

python -m pytest -q
